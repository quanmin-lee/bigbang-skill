## 合并建议

### 架构决策（来自 ARCH.md）

- 基于 lark-oapi 的 WebSocket 长连接 + asyncio 事件驱动架构
- 三层解耦：session 管理器 / LLM 客户端 / 消息编排 handler
- 会话存储使用 SQLite + 内存缓存，支持多用户并发
- V1 最小主链：事件接收 → 会话管理 → LLM 调用 → 回复发送

### 执行计划（来自 EXECUTION_PLAN.md）

- Batch 1 (串行 + 局部并发): T1 → T2 → [T3, T5 并行] → T4 → T6 → T7 → T8
- Batch 2: T9 端到端测试 + T10 单元测试
- T3 与 T5 因无文件冲突可安全并发

### 测试策略（来自 TEST_BOUNDARIES.md）

- pytest + pytest-asyncio + pytest-mock
- SQLite `:memory:` 模式确保测试隔离
- 所有 LLM API 调用必须 mock，避免真实 API 费用
- P0 覆盖：配置验证 / 会话 CRUD / LLM 调用 / 消息编排全链路

### 输入/输出契约

| 组件 | 输入 | 输出 |
|------|------|------|
| session/store.py | session_id, messages | 持久化消息列表 |
| llm/client.py | messages (list[dict]) | reply_text (str) |
| handler/message.py | 飞书 event 对象 | 调用 bot.reply_message |
| bot.py | 飞书 WS event | 事件分发到 handler |

### 关键风险提醒

1. **WebSocket 重连**：lark-oapi 的 ws.Client 是否内置重连机制需确认，否则手动实现指数退避
2. **LLM 费用**：开发和测试阶段务必 mock LLM API，避免产生费用
3. **飞书开发者后台配置**：在启动开发前确认飞书应用已创建、事件订阅已配置、权限已开通
