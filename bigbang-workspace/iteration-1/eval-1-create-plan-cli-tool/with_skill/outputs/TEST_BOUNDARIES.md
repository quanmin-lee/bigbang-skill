# 测试验收边界

## 测试策略

- **测试框架**: `pytest` + `pytest-cov`
- **Mock 策略**: 使用 `tmp_path` fixture 创建临时 Excel 和 CSV 文件；不 mock openpyxl，直接操作真实文件（文件 IO 是本工具的核心功能，mock 会降低测试价值）
- **单元测试 vs 集成测试**:
  - 单元测试覆盖 reader, aggregator, writer 各模块的纯逻辑
  - 集成测试覆盖主流程 main() 的端到端通路
- **测试数据**: 用 openpyxl 在 `tmp_path` 中动态生成测试 Excel 文件，避免依赖外部 fixture 文件

## 按任务分解

### T0: 项目初始化 (P0)
- **验收条件**:
  - `pyproject.toml` 存在且可被 pip 解析
  - `requirements.txt` 包含 openpyxl
  - `tests/` 目录存在，可被 pytest 发现
- **测试场景**: N/A（配置类任务，手动验证）

### T1: CLI 参数解析 (P0)
- **验收条件**:
  - `--input` 参数接收文件路径字符串
  - `--column` 参数接收列名字符串
  - `--output` 参数接收输出文件路径字符串
  - 缺少必需参数时打印用法并退出非零
- **测试场景**:
  | 场景 | 输入 | 预期输出 | 优先级 |
  |------|------|---------|--------|
  | 正常路径 | `--input data.xlsx --column 销售额 --output result.csv` | 返回三个参数值 | P0 |
  | 缺少 --input | `--column 销售额 --output result.csv` | 非零退出 + 提示 | P0 |
  | 缺少 --column | `--input data.xlsx --output result.csv` | 非零退出 + 提示 | P0 |
  | 缺少 --output | `--input data.xlsx --column 销售额` | 非零退出 + 提示 | P0 |
  | --help | `--help` | 打印帮助信息，零退出 | P1 |
- **RED 测试**: `test_cli_parses_all_args` — 测试 argparse 正确解析三个参数
- **GREEN 最小实现**: 用 argparse 定义三个 `--` 前缀参数，均为 `required=True`

### T2: Excel 读取模块 (P0)
- **验收条件**:
  - 正确读取 .xlsx 文件中指定列的所有数值数据
  - 返回 `list[dict]` 格式：`[{"销售额": 100, "类别": "A"}, ...]`
  - 第一行为表头（列名）
  - 只处理第一个 sheet
- **测试场景**:
  | 场景 | 输入 | 预期输出 | 优先级 |
  |------|------|---------|--------|
  | 正常 Excel | 含 3 行数据、2 列（类别/销售额）的 xlsx | `[{"类别":"A","销售额":100}, ...]` | P0 |
  | 空文件 | 只有表头、无数据行的 xlsx | 空列表 `[]` | P1 |
  | 列名不存在 | 指定不存在的列名 | 抛出 `ValueError` | P1 |
  | 含空值单元格 | 某行指定列为空 | 该行仍返回，空值字段为 `None` | P2 |
- **RED 测试**: `test_reader_returns_rows` — 读取已知内容的 xlsx，验证返回数据正确
- **GREEN 最小实现**: 用 `openpyxl.load_workbook` 读取 active sheet，遍历行，用表头构建 dict

### T3: 数据聚合逻辑 (P0)
- **验收条件**:
  - 按 `--column` 指定的列分组聚合（默认 sum）
  - 分组键为列中不同的值
  - 返回 `list[dict]`：`[{"类别": "A", "销售额": 300}, ...]`
- **测试场景**:
  | 场景 | 输入 | 预期输出 | 优先级 |
  |------|------|---------|--------|
  | 正常聚合 | `[{"类别":"A","销售额":100}, {"类别":"A","销售额":200}]` + column="销售额" | `[("A", 300)]` | P0 |
  | 单一分组 | 所有行同组 | 一条汇总结果 | P0 |
  | 空列表 | 空输入 | 空列表 | P1 |
  | 非数值数据 | 某行销售额为字符串 | 抛出或跳过（V1 约定抛出 TypeError） | P1 |
- **RED 测试**: `test_aggregator_sums_by_column` — 按指定列分组求和
- **GREEN 最小实现**: 用 `itertools.groupby` 或手动 dict 聚合，遍历行，按分组键累加

### T4: CSV 输出模块 (P0)
- **验收条件**:
  - 将聚合结果写入指定路径的 CSV 文件
  - CSV 包含表头行
  - 正确编码 UTF-8
- **测试场景**:
  | 场景 | 输入 | 预期输出 | 优先级 |
  |------|------|---------|--------|
  | 正常写入 | `[{"类别":"A","销售额":300}]`, path="out.csv" | `out.csv` 内容为 `类别,销售额\nA,300` | P0 |
  | 空结果 | 空列表 | CSV 仅含表头、无数据行 | P1 |
  | 输出路径不存在 | 路径包含不存在的目录 | 自动创建目录或抛出清晰错误 | P2 |
- **RED 测试**: `test_writer_creates_csv` — 写入后读取验证内容
- **GREEN 最小实现**: 用 `csv.DictWriter` 写入

### T5: 主流程编排 (P0)
- **验收条件**:
  - `python main.py --input test.xlsx --column 销售额 --output result.csv` 完整跑通
  - 生成的 result.csv 内容正确
- **测试场景**:
  | 场景 | 输入 | 预期输出 | 优先级 |
  |------|------|---------|--------|
  | 端到端正常 | 构造的 xlsx → 指定列 → 聚合 → 输出 | CSV 内容与手算一致 | P0 |

### T6: 错误处理 (P1)
- **验收条件**:
  - 文件不存在 → 打印错误信息 + 非零退出
  - 列名不存在 → 打印可用列名 + 非零退出
  - 非数值数据 → warning 信息（V1 跳过）
- **测试场景**:
  | 场景 | 输入 | 预期输出 | 优先级 |
  |------|------|---------|--------|
  | 输入文件不存在 | `--input nonexistent.xlsx` | 错误退出 + 友好提示 | P1 |
  | 错误列名 | 指定列不存在 | 打印可用列名 | P1 |
  | 非 .xlsx 文件 | 传入 .csv 文件 | 错误退出 + 提示只支持 .xlsx | P2 |

## 测试执行顺序

1. **T1、T2、T3、T4 可并行测试**（各自独立）
2. T5 集成测试需要所有模块就绪后执行
3. T6 错误处理测试可看作 T5 的补充，与 T5 同批次

## 注意事项

- openpyxl 需要 `.xlsx` 文件存在才能创建 `Workbook`；测试中用 `tmp_path / "test.xlsx"` 作为路径
- 确保测试用 Excel 在 Python 3.10+ 和 openpyxl 3.x 下兼容
- 聚合逻辑的精度：浮点数聚合可能产生微小精度差异，测试断言用 `pytest.approx` 而非精确 `==`
