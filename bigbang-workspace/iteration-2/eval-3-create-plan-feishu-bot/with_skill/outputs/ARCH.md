# 架构评估报告

## 需求理解

构建一个飞书机器人项目，核心能力：
1. **接收用户消息** — 通过飞书 Webhook/Event 订阅接收用户发送的消息
2. **调用 LLM 生成回复** — 将用户消息传递给大语言模型，获取智能回复
3. **支持多轮对话** — 保持对话上下文，实现连续多轮交互

## 项目概览

### 主要模块与职责

| 模块 | 职责 |
|------|------|
| **消息接收层** | 飞书 Event Callback / Webhook 入口，解析飞书消息事件 |
| **会话管理层** | 维护每个用户/群的对话历史，支持上下文窗口和过期策略 |
| **LLM 调用层** | 封装 LLM API 调用（支持多模型切换、重试、退避） |
| **回复发送层** | 调用飞书 API 发送消息（文本、富文本、卡片） |
| **配置管理层** | 机器人配置（Token、App ID、LLM 参数等） |

### 关键数据流

```
飞书用户 → 飞书服务器 → Webhook/Event Subscription
    → 消息接收层（验证签名/Token）
    → 会话管理层（获取/创建会话上下文）
    → LLM 调用层（组装 Prompt + 历史 → 调用 API → 解析回复）
    → 回复发送层（格式化消息 → 调用飞书 Send Message API）
    → 飞书用户收到回复
```

### 技术栈建议

| 层 | 技术选型 |
|----|---------|
| 运行时 | Python 3.11+ |
| Web 框架 | FastAPI (异步, 原生支持飞书回调) |
| 飞书 SDK | lark-oapi (官方 Python SDK) |
| LLM SDK | OpenAI SDK / Anthropic SDK (或统一调用层) |
| 会话存储 | SQLite (单机) / Redis (生产) / 内存 (开发) |
| 部署 | Uvicorn + systemd / Docker |

## V2+ 建议

- **持久化会话存储**: 从内存存储升级到 Redis/SQLite，支持服务重启后恢复会话
- **富文本/卡片消息**: 支持飞书消息卡片，提供更丰富的交互
- **多模型支持**: 支持切换不同 LLM 模型（GPT-4, Claude, 文心等）
- **指令系统**: 支持 `/command` 系统命令（清空上下文、切换模型等）
- **管理后台**: Web 管理界面查看会话、调整配置
- **监控与日志**: 接入 Prometheus + Grafana, 结构化日志
- **多轮上下文压缩**: 超长上下文时自动摘要历史

## 风险与注意事项

1. **飞书 API 限频**: 飞书发送消息 API 有频率限制（QPS），需实现队列和退避
2. **LLM API 延迟**: LLM 响应时间不稳定（1-10s），需设置合理的超时和用户等待反馈
3. **签名验证**: 飞书回调必须验证签名，防止伪造请求（安全风险高）
4. **Token 管理**: tenant_access_token 有有效期（2h），需实现自动刷新
5. **多轮上下文长度**: 不加控制的历史拼接会导致 Token 消耗爆炸，需实现窗口截断
